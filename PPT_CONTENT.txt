SLIDE 2 — PROBLEM STATEMENT
--------------------------------------------------------------------------------
The Problem with Traditional Bank Queues

Customers wait 30 to 90 minutes without knowing their turn.
No way to plan visits in advance.
Overcrowding during peak hours causes chaos.
No real-time visibility for staff or customers.
Manual token systems are error-prone and inefficient.

Result: Poor customer experience and inefficient bank operations.


SLIDE 3 — OUR SOLUTION
--------------------------------------------------------------------------------
BankQ — Smart Queue Management

A full-stack web application that allows customers to pre-book time slots
from home, check in at the branch using a QR code, and track their token
status in real time on any device.

Customers pre-book 30-minute time slots online.
System auto-generates tokens like C-101 and L-102.
QR code is scanned at the branch entrance for check-in.
Live WebSocket dashboard shows queue status in real time.
Teller dashboard manages customer flow at counters.
Role-based access for all bank staff and customers.


SLIDE 4 — KEY FEATURES
--------------------------------------------------------------------------------
Core Features

Slot Booking — Book 30-minute slots, choose branch and service
Token Generation — Auto tokens like C-101 and W-102 per service type
QR Check-In — SHA-256 QR hash scanned at entrance by security
Live Tracker — Real-time WebSocket queue dashboard for all users
PAN Validation — Automatically triggered for deposits above 50000 rupees
Lunch Break Guard — Slots blocked during configured branch lunch hours
Double Booking Block — Same customer cannot book the same slot twice
Role Based Access — Four roles: Customer, Teller, Security, and Admin

SLIDE 8 — TOKEN LIFECYCLE
--------------------------------------------------------------------------------
How a Token Moves Through the System

Step 1 — BOOKED
Customer books a slot online and receives a token and QR hash.

Step 2 — CHECKED_IN
Security guard scans the QR code at the branch entrance.

Step 3 — IN_PROGRESS
Teller calls the next token from the dashboard.

Step 4 — COMPLETED
Teller marks the service as done after serving the customer.

CANCELLED — Can happen at any point before IN_PROGRESS.

Every status change instantly broadcasts a live WebSocket event
to all clients watching that branch.

SLIDE 10 — REAL-TIME WEBSOCKET FLOW
--------------------------------------------------------------------------------
Real-Time Queue Broadcasting

WebSocket connects to the server at ws://server/ws/queue/{branch_id}

Customer books a slot and receives Token C-101 and a QR Hash.

Security scans QR at entrance.
Backend updates status to CHECKED_IN.
Broadcasts event CHECKED_IN with token C-101 to all watchers.

Teller clicks Call Next Token.
Backend updates status to IN_PROGRESS.
Broadcasts event CALLED with token C-101 and counter number.

Teller clicks Mark Complete.
Backend updates status to COMPLETED.
Broadcasts event COMPLETED with token C-101.

All connected clients on that branch receive every event instantly.
Multiple branches run completely independent WebSocket channels.


SLIDE 11 — SECURITY IMPLEMENTATION
--------------------------------------------------------------------------------
Security Features

Authentication — JWT Bearer tokens using HS256 algorithm with 60 minute expiry.
Passwords — bcrypt hashing with unique salt per user, one-way irreversible.
Authorization — Role-based guards enforced on every protected API endpoint.
PAN Compliance — RBI regulation enforced, PAN required for deposits above 50000.
QR Security — SHA-256 hash generated from customer ID, branch, slot, and date.
Double Check-In Prevention — QR can only be verified once when status is BOOKED.
Input Validation — Pydantic v2 schema validation on all incoming API requests.
