1. THE BIG PICTURE
--------------------------------------------------------------------------------

BankQ works exactly like a token system at a real bank, but digital:

  CUSTOMER  →  Books a slot online  →  Gets Token (C-101) + QR Code
  CUSTOMER  →  Arrives at bank      →  Security scans QR at entrance
  SECURITY  →  Scans QR             →  Customer is CHECKED IN
  TELLER    →  Calls next token     →  Customer goes to counter
  TELLER    →  Marks complete       →  Next customer is called
  EVERYONE  →  Watches Live Tracker →  Sees all updates in real time

No physical waiting in line. No confusion about whose turn it is.
Everything is visible on screen, live.

3. TOKEN LIFECYCLE — HOW A TOKEN MOVES
--------------------------------------------------------------------------------

  Every appointment has a STATUS that moves in one direction:

  BOOKED  ──►  CHECKED_IN  ──►  IN_PROGRESS  ──►  COMPLETED
                                                        │
                              CANCELLED ◄──────────────┘
                              (can cancel before IN_PROGRESS)

  BOOKED       Customer booked the slot online. Not yet at the bank.
  CHECKED_IN   Security scanned the QR at entrance. Customer is inside.
  IN_PROGRESS  Teller called this token. Customer is at the counter.
  COMPLETED    Service done. Teller marked it complete.
  CANCELLED    Appointment was cancelled before service started.

  Token format:  {ServicePrefix}-{Number}
  Examples:
    C-101  →  Cash Deposit (C), first token of the day
    W-101  →  Cash Withdrawal
    L-101  →  Loan Inquiry
    A-101  →  Account Opening
    D-101  →  Demand Draft

  8. NOW switch to the Live Tracker tab

5. WHAT EACH PAGE DOES
--------------------------------------------------------------------------------

  /auth  —  Auth Page (Login / Register)
  ----------------------------------------
  Two tabs: Login and Register
  Login uses phone number as username + password
  After login, you are redirected based on your role:
    CUSTOMER  →  /book
    TELLER    →  /teller
    SECURITY  →  /kiosk
    ADMIN     →  /teller

  /book  —  Book Slot (CUSTOMER, ADMIN)
  ---------------------------------------
  Select Branch, Service, Date, Time Slot (30-min intervals, 9AM–5PM)
  Lunch break slots (1:00 PM, 1:30 PM) are blocked
  If deposit > ₹50,000 → PAN number field appears and is required
  On success → shows Token number and QR Hash
  Double booking is prevented (same customer, branch, date, slot)

  /track  —  Live Tracker (CUSTOMER, ADMIN)
  ------------------------------------------
  Select a branch to connect via WebSocket
  Shows 3 live stats:
    Now Serving  →  current token being served
    Waiting      →  number of checked-in customers
    Est. Wait    →  estimated wait time in minutes
  Paste your QR Hash to see your queue position and a QR code image
  Live Event Feed shows last 20 events with timestamps
  Events: CHECKED_IN (green), CALLED (blue), COMPLETED (grey)

  /kiosk  —  Kiosk Scanner (SECURITY, ADMIN)
  --------------------------------------------
  Input box for QR Hash (works with barcode scanners too — press Enter)
  Shows ✅ success or ❌ error with reason
  Keeps a history of last 10 scans with timestamps
  Only works on BOOKED appointments (prevents double check-in)

  /teller  —  Teller Dashboard (TELLER, ADMIN)
  ----------------------------------------------
  Select Branch and Counter
  Counter Status toggle — ON means accepting customers
  "Call Next Token" — pulls the oldest CHECKED_IN customer
    (ordered by slot time, then appointment ID — first booked, first served)
  "Mark Complete" — marks current token as COMPLETED
  Currently Serving display shows active token in large text

6. REAL-TIME WEBSOCKET — HOW IT WORKS
--------------------------------------------------------------------------------

  The Live Tracker connects to:
    ws://localhost:9000/ws/queue/{branch_id}

  Every time a status changes via the API, the backend broadcasts
  a JSON event to ALL connected clients watching that branch:

  On CHECKED_IN (kiosk verify):
    { "event": "CHECKED_IN", "token": "C-101", "appointment_id": 1 }

  On CALLED (teller call-next):
    { "event": "CALLED", "token": "C-101", "counter": 1, "appointment_id": 1 }

  On COMPLETED (teller complete):
    { "event": "COMPLETED", "token": "C-101", "appointment_id": 1 }

  Multiple people can watch the same branch simultaneously.
  All of them receive the same events at the same time.
  This is why opening 4 tabs and doing the flow shows everything live.

9. COMMON QUESTIONS
--------------------------------------------------------------------------------

  Q: Why is the Live Tracker feed empty when I open it?
  A: It only shows events that happen AFTER you connect. Past events
     (like the seeded dummy data) don't appear. Do the 4-tab test
     to see it work live.

  Q: Why can't I book the same slot twice?
  A: Double-booking is blocked. Same customer + branch + date + time
     will return a 409 Conflict error.

  Q: Why is the 1:00 PM and 1:30 PM slot missing?
  A: That's the lunch break. Branches have a 1-hour lunch window
     configured (1:00 PM - 2:00 PM for most branches).

  Q: What happens if I scan a QR that's already CHECKED_IN?
  A: The kiosk returns an error: "Token already in status: CHECKED_IN"
     Prevents customers from checking in twice.

  Q: Can multiple tellers work at the same time?
  A: Yes. Each teller selects their own counter. Call Next always
     picks the oldest waiting customer regardless of which teller calls.

  Q: What does the PAN field do?
  A: RBI regulation — any cash deposit above ₹50,000 requires a PAN
     number. The field only appears when deposit amount exceeds that.
     Format must be: 5 letters + 4 digits + 1 letter (e.g. ABCDE1234F)
