ABSTRACT
================================================================================

This project focuses on the development of BankQ, a Bank Queue Management System integrated with a Generative AI-powered chatbot, using modern web technologies and Generative Artificial Intelligence.

The existing approach to bank queue management faces challenges such as long physical waiting times, lack of real-time queue visibility, no prior appointment scheduling, and absence of intelligent customer assistance. To address these issues, the proposed system uses the Groq AI API (LLM-based) to provide an intelligent conversational assistant that answers customer queries related to banking services and queue management.

The application is developed using FastAPI (Python) for the backend, React with Vite and Tailwind CSS for the frontend, and MySQL as the database. The Generative AI component is used for natural language question answering, allowing customers to interact with a floating AI chatbot for instant assistance.

The system provides features such as online slot booking, 4-digit PIN-based kiosk check-in, real-time queue tracking via WebSockets, teller dashboard for queue management, appointment history, and an AI chatbot assistant powered by Groq AI. The project is evaluated through functional testing and AI output evaluation.

The proposed application aims to improve customer experience, reduce physical waiting time, and provide intelligent assistance at bank branches. The project also identifies limitations and opportunities for future enhancement such as mobile app support and multilingual chatbot responses.

1.1 Introduction to the Project

BankQ is a Bank Queue Management System developed to modernize and streamline the customer experience at bank branches. The system allows customers to book appointment slots online, check in at the branch using a 4-digit PIN at a kiosk, and track their queue status in real time. An AI-powered chatbot is integrated to assist customers with queries related to banking services, slot booking, and queue management.

The project is developed as part of the MCA Semester III Generative AI subject, demonstrating the practical integration of a Large Language Model (LLM) API into a full-stack web application.

1.2 Background of the Project

Traditional bank queue management relies on physical token dispensers and manual processes. Customers arrive at the branch without prior appointments, leading to overcrowding and long wait times. With the advancement of web technologies and Generative AI, it is now feasible to build intelligent systems that allow customers to pre-book slots, receive digital tokens, and interact with AI assistants for instant help.

Groq AI provides a fast and free LLM API that enables natural language understanding and response generation, making it suitable for a banking chatbot use case.

1.3 Motivation

The motivation for this project includes:
- Reducing physical waiting time at bank branches.
- Providing customers with a convenient online slot booking system.
- Enabling real-time queue visibility for customers and tellers.
- Integrating Generative AI to provide intelligent customer assistance without human intervention.
- Demonstrating practical use of LLM APIs in a real-world application.

1.4 Problem Statement

To design and develop a Bank Queue Management System using Generative Artificial Intelligence to address the problem of unorganized bank queues and lack of customer assistance by providing online slot booking, PIN-based kiosk check-in, real-time queue tracking, and an AI chatbot to bank customers.

1.5 Objectives of the Project

1. To study existing methods used for bank queue management.

5. To evaluate the usefulness and performance of the application using functional test cases.
6. To identify system limitations and opportunities for improvement.

- Main features: Online slot booking, PIN-based check-in, real-time queue tracking, teller dashboard, appointment history, AI chatbot.
- AI capability: Natural language question answering for BankQ-related queries using Groq AI.
- Platform: Web application accessible via browser.
- Boundaries: The system manages queues for three demo branches (Bangalore, Delhi, Mumbai) and five services.

CHAPTER 2: EXISTING SYSTEM AND PROBLEM ANALYSIS
================================================================================

2.1 Overview of the Existing System

In the existing system, customers visit the bank branch in person to obtain a physical token from a token dispenser machine or from a bank staff member. They then wait in the branch until their token number is called. There is no prior appointment system, no digital queue visibility, and no intelligent assistance available to customers.

2.2 Working of the Existing System

1. Customer arrives at the bank branch.
2. Customer collects a physical token from the dispenser.
3. Customer waits in the branch seating area.
4. Teller calls the next token number verbally or via a display board.
5. Customer approaches the counter for service.
6. Service is completed and customer leaves.

2.3 Limitations of the Existing System

- Customers must physically visit the branch to get a token, even for simple services.
- No prior appointment booking is possible, leading to unpredictable wait times.
- No real-time queue visibility for customers waiting outside the branch.
- No intelligent assistance for customer queries; customers must ask staff manually.
- Long queues during peak hours cause customer dissatisfaction.
- No digital record of customer appointments or service history.
- Security staff cannot verify customers digitally.

2.4 Literature Review

[1] Various bank queue management systems have been proposed using SMS-based token systems, but these lack real-time web interfaces and AI integration.
[2] Chatbot integration in banking has been studied using rule-based systems, but LLM-based chatbots provide more natural and flexible responses.
[3] FastAPI and React have been widely adopted for building modern full-stack web applications due to their performance and developer experience.
[4] Groq AI provides one of the fastest LLM inference APIs available, making it suitable for real-time chatbot applications.

2.5 Comparative Analysis

Feature              Existing System                  Proposed System (BankQ)
User Interaction     Physical visit required          Online booking via web app
Appointment          No prior booking                 Online slot booking (9AM-5PM)
Check-in             Physical token collection        4-digit PIN at kiosk
Queue Visibility     Only inside branch               Real-time via Live Tracker
AI Integration       None                             Groq AI LLM chatbot
Customer Assistance  Manual (ask staff)               AI chatbot available 24/7
Token Management     Paper-based                      Digital token with prefix
Data Management      No digital records               MySQL database with history
Limitations          Long waits, no digital access    Internet dependency, API limits

2.6 Problem Identification

- Customers waste time waiting at the branch without knowing queue status.
- No system exists for pre-booking appointments at bank branches.
- Customers have no digital channel to get answers to common banking queries.
- Security staff cannot verify customer appointments digitally.

2.7 Need for the Proposed System

A web-based queue management system with AI assistance is justified because it eliminates physical waiting, provides digital appointment management, enables real-time queue tracking, and offers intelligent customer support through a Generative AI chatbot — all of which are absent in the existing system.

CHAPTER 3: PROPOSED SYSTEM
================================================================================

3.1 Introduction

BankQ is a full-stack web application that replaces the traditional physical queue system with a digital, AI-assisted platform. Customers can book slots online, check in at the kiosk using a PIN, and track their queue status in real time. An AI chatbot powered by Groq AI assists customers with queries.

3.2 Overview of the Proposed System

The system consists of a React frontend, a FastAPI backend, and a MySQL database. Customers register and log in to book appointment slots. On arrival, they enter their 4-digit PIN at the kiosk to check in. Tellers use the dashboard to call the next customer. The Live Tracker page shows real-time queue updates via WebSockets. The AI chatbot answers customer queries using the Groq AI LLM API.

CHAPTER 4: GENERATIVE AI COMPONENTS USED
================================================================================

4.1 Introduction to Generative AI

Generative Artificial Intelligence refers to AI systems that can generate new content — such as text, images, or code — based on input prompts. Large Language Models (LLMs) are a class of Generative AI that are trained on large text datasets and can understand and generate human-like text responses. In BankQ, a Generative AI LLM is used to power the customer-facing chatbot, enabling natural language interaction for banking queries.

4.2 Generative AI Model Used

Provider: Groq AI (https://groq.com)
Model: openai/gpt-oss-20b
Access Method: REST API via HTTP POST request
Purpose: Natural language question answering for BankQ and banking-related customer queries
API Endpoint: https://api.groq.com/openai/v1/chat/completions
Authentication: Bearer token (API key)

4.3 Generative AI Components

Component            Description                          Use in Project
Large Language Model Generates text responses             Answers customer queries in chatbot
Prompt Engineering   Structures instructions for model    System prompt defines BankQ context
API Integration      Connects app to Groq AI service      httpx async HTTP POST from FastAPI
Output Processing    Extracts reply from API response     Parses choices[0].message.content
Error Handling       Handles API failures                 Returns fallback message on exception

4.4 Prompt Engineering and Design

The system uses a system prompt to constrain the AI to BankQ and banking-related topics only.

System Prompt used in BankQ:
"You are BankQ Assistant, a helpful chatbot for BankQ - a bank queue management system.
The bank offers: Cash Deposit, Cash Withdrawal, Loan Inquiry, Account Opening, Demand Draft.
Branches in Bangalore, Delhi, Mumbai. Customers book slots online (9AM-5PM, 30-min slots)
and check in with a 4-digit PIN at the kiosk. ONLY answer BankQ and banking related questions.
If asked anything unrelated, politely say you can only help with BankQ topics. Be short and friendly."

This prompt:
- Defines the role of the AI (BankQ Assistant)
- Provides context about services, branches, and features
- Constrains responses to BankQ/banking topics only
- Sets tone (short and friendly)

Example interaction:
User: "How do I book a slot?"
AI: "To book a slot, log in to BankQ, click 'Book Slot', select your branch, service, date and time, and confirm. You will receive a token number and a 4-digit PIN."

4.5 Workflow of the Generative AI Component

1. Customer types a message in the floating chatbot UI.
2. Frontend sends POST /api/ai/chat with { "message": "..." } to FastAPI backend.
3. FastAPI constructs the request with system prompt + user message.
4. httpx sends async POST to Groq AI API endpoint with Bearer token.
5. Groq AI LLM generates a response.
6. FastAPI extracts the reply text from the JSON response.
7. Reply is returned to the frontend as { "reply": "..." }.
8. Frontend displays the reply in the chat window.

4.6 Model Parameters and Configuration

Parameter            Value
Model                openai/gpt-oss-20b
Max Tokens           200
Temperature          Default (not explicitly set)
System Prompt        BankQ context (see 4.4)
Timeout              15 seconds

4.7 AI Output Validation

- If the Groq API returns an error or times out, the backend catches the exception and returns: "I can only help with BankQ and banking related questions. Try asking about booking a slot, services, branches, or kiosk check-in!"
- The system prompt instructs the model to redirect off-topic questions politely.
- Responses are limited to 200 tokens to keep answers concise.
- The frontend shows a "Thinking..." indicator while waiting for the response.

4.8 Responsible AI Considerations

- Data Privacy: No personal customer data is sent to the Groq AI API. Only the user's chat message is transmitted.
- API Key Protection: The Groq API key is stored only in the backend (main.py) and never exposed to the frontend.
- Bias and Fairness: The chatbot is restricted to BankQ topics, minimizing risk of biased responses.
- Human Oversight: The chatbot is advisory only. All actual transactions are handled by bank staff.
- Misinformation: The system prompt constrains the AI to factual BankQ information only.
- Ethical Use: The chatbot is used solely for customer assistance, not for any automated decision-making.

4.9 Role of Generative AI in the Project

Generative AI (Groq LLM) is used specifically for the chatbot module — natural language understanding and response generation. All other features (slot booking, PIN generation, queue management, WebSocket updates, authentication) are implemented using conventional programming with FastAPI, React, and MySQL.

CHAPTER 7: IMPLEMENTATION

7.1 Introduction

The BankQ system was implemented as a full-stack web application with a FastAPI backend, React frontend, and MySQL database. The Groq AI API was integrated for the chatbot module. 7.3 Implementation of Modules

Authentication Module (auth.py):
- POST /auth/register: Validates last4 digits against bank_accounts table, hashes password with bcrypt, creates user with CUSTOMER role.
- POST /auth/login: Verifies credentials, returns JWT token.
- get_current_user: Decodes JWT, fetches user from DB.

Slot Booking Module (main.py - /appointments/book):
- Checks for duplicate bookings.
- Generates SHA-256 QR hash and random 4-digit PIN.
- Creates token with service prefix (e.g., CD-101 for Cash Deposit).
- Saves appointment to MySQL.

Kiosk Module (main.py - /kiosk/verify):
- Accepts PIN, finds appointment, marks as CHECKED_IN.
- Broadcasts WebSocket event to all connected clients for that branch.

Teller Module (main.py - /teller/call-next, /teller/complete):
- Fetches next CHECKED_IN appointment ordered by slot time.
- Marks as IN_PROGRESS or COMPLETED and broadcasts WebSocket event.

AI Chatbot Module (main.py - /ai/chat):
- Receives user message from frontend.
- Constructs request with system prompt + user message.
- Sends async POST to Groq AI API using httpx.
- Returns AI-generated reply to frontend.

7.4 AI Model Integration

Code snippet (main.py):

  @app.post("/ai/chat")
  async def ai_chat(req: ChatRequest):
      try:
          async with httpx.AsyncClient(timeout=15) as client:
              resp = await client.post(
                  GROQ_URL,
                  headers={"Authorization": f"Bearer {GROQ_API_KEY}"},
                  json={
                      "model": "openai/gpt-oss-20b",
                      "messages": [
                          {"role": "system", "content": BANK_CONTEXT},
                          {"role": "user", "content": req.message},
                      ],
                      "max_tokens": 200,
                  },
              )
              result = resp.json()
              reply = result["choices"][0]["message"]["content"]
              return {"reply": reply}
      except Exception:
          return {"reply": "I can only help with BankQ and banking related questions."}

7.8 Error Handling

- Invalid login: 401 Unauthorized returned by backend, displayed as error message on frontend.
- Duplicate booking: 409 Conflict returned, shown as alert.
- Invalid PIN at kiosk: 404 Not Found returned, shown as error.
- Groq AI API failure: Exception caught, fallback message returned.
- Empty chat input: Send button disabled when input is empty.
- Network errors: Axios catch block shows "Something went wrong" message.

CHAPTER 9: SCOPE, LIMITATIONS AND FUTURE ENHANCEMENTS

9.1 Scope of the Project

BankQ is scoped for demo use with 3 branches (Bangalore, Delhi, Mumbai), 5 banking services, and 4 user roles (Customer, Teller, Security, Admin). The system supports online slot booking, PIN-based check-in, real-time queue tracking, and AI-assisted customer support via web browser.

9.2 Limitations of the Project

- The system depends on the Groq AI API for chatbot functionality; internet connectivity is required.
- Groq AI free tier has rate limits which may affect chatbot availability under heavy usage.
- The AI model may occasionally generate responses that are slightly off-topic despite the system prompt.
- The application is a demo system; it is not connected to a real bank's core banking system.
- No mobile application is available; the system is web-only.
- The system currently supports English language only.
- QR code scanning is not implemented; only PIN-based check-in is available.

9.3 Future Enhancements

- Integration with real bank core banking systems for live data.
- Development of a mobile application (Android/iOS).
- Multilingual chatbot support for regional languages.
- Voice-based interaction with the AI chatbot.
- QR code scanning at kiosk in addition to PIN.
- SMS/email notifications for booking confirmation and queue updates.
- AI-based queue wait time prediction.
- Admin dashboard with analytics and reports.
- Improved AI output validation to further reduce off-topic responses.
- Deployment on cloud (AWS/Azure) for production use.

9.4 Social and Practical Applications

BankQ can significantly reduce customer waiting time at bank branches, improve customer satisfaction, and reduce the workload on bank staff for routine queries. The AI chatbot provides 24/7 assistance without requiring additional human resources. The system can be adapted for other queue-based services such as hospitals, government offices, and service centers.

9.5 Sustainability and Maintainability

The modular architecture (separate frontend and backend) makes the system easy to maintain and extend. New services, branches, or features can be added by updating the database and adding new API endpoints. The Groq AI model can be swapped for any OpenAI-compatible API without changing the frontend. The codebase uses standard, well-documented technologies ensuring long-term maintainability.
