                    booking details (branch, service, date, slot)

                    live queue status + estimated wait time
  [CUSTOMER] ◄─────────────────────────────────────────────────────

                    QR hash scan input
  [SECURITY] ─────────────────────────────────────────────────────►

  [SECURITY] ◄─────────────────────────────────────────────────────

--------------------------------------------------------------------------------
  DFD LEVEL 1 — MAIN PROCESSES
--------------------------------------------------------------------------------

  Level 1 breaks the single system bubble into 6 main processes.

  EXTERNAL ENTITIES:  [CUSTOMER]  [TELLER]  [SECURITY]  [ADMIN]

  DATA STORES:
    D1  users          — user credentials and role data
    D2  appointments   — all booking records and status
    D3  branches       — branch config and lunch hours
    D4  services       — service catalogue and token prefix
    D5  counters       — counter and teller assignments


  ┌─────────────────────────────────────────────────────────────────────────┐
  │  PROCESS 1.0 — AUTHENTICATE USER                                        │
  │                                                                         │
  │  Input  : phone_number + password  from [CUSTOMER/TELLER/SECURITY/ADMIN]│
  │  Read   : D1 users (fetch password_hash by phone_number)                │
  │  Process: bcrypt.verify(password, hash) → generate JWT token            │
  │  Output : Bearer JWT token → to requesting user                         │
  └─────────────────────────────────────────────────────────────────────────┘
                │
                │ JWT token (used in all subsequent processes)
                ▼

  ┌─────────────────────────────────────────────────────────────────────────┐
  │  PROCESS 2.0 — BOOK APPOINTMENT                    [CUSTOMER]           │
  │                                                                         │
  │  Input  : branch_id, service_id, booking_date, slot_start_time,        │
  │           deposit_amount (optional), pan_number (conditional)           │
  │  Read   : D3 branches (validate branch, check lunch hours)              │
  │  Read   : D4 services (get service_code_prefix)                         │
  │  Read   : D2 appointments (double-booking check)                        │
  │  Process: validate PAN if deposit > 50000                               │
  │           generate token = prefix + sequential number                   │
  │           generate qr_hash = SHA256(customer+branch+slot+date)          │
  │  Write  : D2 appointments (new record, status = BOOKED)                 │
  │  Output : token_number + qr_hash → [CUSTOMER]                          │
  └─────────────────────────────────────────────────────────────────────────┘
                │
                │ qr_hash delivered to customer
                ▼

  ┌─────────────────────────────────────────────────────────────────────────┐
  │  PROCESS 3.0 — KIOSK VERIFY (CHECK-IN)             [SECURITY]          │
  │                                                                         │
  │  Input  : qr_hash (scanned at branch entrance)                         │
  │  Read   : D2 appointments (lookup by qr_hash)                          │
  │  Process: validate status == BOOKED (reject if already checked in)      │
  │           update status = CHECKED_IN                                    │
  │  Write  : D2 appointments (status updated)                              │
  │  Output : confirmation + token_number → [SECURITY]                     │
  │  Trigger: broadcast CHECKED_IN event via WebSocket to all branch viewers│
  └─────────────────────────────────────────────────────────────────────────┘
                │
                │ CHECKED_IN event broadcast
                ▼

  ┌─────────────────────────────────────────────────────────────────────────┐
  │  PROCESS 4.0 — CALL NEXT TOKEN                     [TELLER]             │
  │                                                                         │
  │  Input  : branch_id + counter_id                                       │
  │  Read   : D5 counters (validate counter belongs to branch)              │
  │  Read   : D2 appointments (oldest CHECKED_IN by slot_time + appt_id)   │
  │  Process: assign counter_id to appointment                              │
  │           update status = IN_PROGRESS                                   │
  │  Write  : D2 appointments (status + counter_id updated)                 │
  │  Output : token_number + counter_number → [TELLER]                     │
  │  Trigger: broadcast CALLED event via WebSocket to all branch viewers    │
  └─────────────────────────────────────────────────────────────────────────┘
                │
                │ IN_PROGRESS event broadcast
                ▼

  ┌─────────────────────────────────────────────────────────────────────────┐
  │  PROCESS 5.0 — COMPLETE TOKEN                      [TELLER]             │
  │                                                                         │
  │  Input  : appointment_id                                               │
  │  Read   : D2 appointments (validate status == IN_PROGRESS)             │
  │  Process: update status = COMPLETED                                     │
  │  Write  : D2 appointments (status updated)                              │
  │  Output : confirmation + token_number → [TELLER]                       │
  │  Trigger: broadcast COMPLETED event via WebSocket to all branch viewers │
  └─────────────────────────────────────────────────────────────────────────┘
                │
                │ COMPLETED event broadcast
                ▼

  ┌─────────────────────────────────────────────────────────────────────────┐
  │  PROCESS 6.0 — LIVE QUEUE BROADCAST                [ALL USERS]          │
  │                                                                         │
  │  Input  : branch_id (WebSocket subscription from client)               │
  │  Process: ConnectionManager maintains dict[branch_id → [WebSocket]]    │
  │           Processes 3, 4, 5 trigger broadcast() on status change       │
  │  Output : JSON event pushed to all connected clients of that branch     │
  │           { event, token, counter, appointment_id }                    │
  └─────────────────────────────────────────────────────────────────────────┘


--------------------------------------------------------------------------------
  DFD LEVEL 2 — PROCESS 2.0 BOOK APPOINTMENT (EXPLODED)
--------------------------------------------------------------------------------

  This explodes Process 2.0 into its internal sub-processes.

  Input from [CUSTOMER]: branch_id, service_id, date, slot, deposit, pan

  ┌──────────────────────────────────────────────────────────────────────┐
  │  PROCESS 2.1 — VALIDATE JWT & ROLE                                   │
  │  Input  : Bearer token from request header                           │
  │  Process: jwt.decode → extract user_id and role                      │
  │  Read   : D1 users (confirm user exists)                             │
  │  Output : authenticated customer object                              │
  │  Error  : 401 Unauthorized if token invalid or expired               │
  └──────────────────────────────────────────────────────────────────────┘
                │ authenticated customer
                ▼
  ┌──────────────────────────────────────────────────────────────────────┐
  │  PROCESS 2.2 — CHECK DOUBLE BOOKING                                  │
  │  Input  : customer_id, branch_id, booking_date, slot_start_time      │
  │  Read   : D2 appointments                                            │
  │  Process: query for same customer+branch+date+slot where             │
  │           status NOT IN (CANCELLED)                                  │
  │  Output : conflict flag                                              │
  │  Error  : 409 Conflict if slot already booked                        │
  └──────────────────────────────────────────────────────────────────────┘
                │ no conflict confirmed
                ▼
  ┌──────────────────────────────────────────────────────────────────────┐
  │  PROCESS 2.3 — VALIDATE BRANCH & LUNCH HOURS                         │
  │  Input  : branch_id, slot_start_time                                 │
  │  Read   : D3 branches (lunch_start_time, lunch_end_time)             │
  │  Process: check slot_start_time NOT between lunch_start and lunch_end │
  │  Output : branch object                                              │
  │  Error  : 400 Bad Request if slot falls in lunch break               │
  └──────────────────────────────────────────────────────────────────────┘
                │ branch validated
                ▼
  ┌──────────────────────────────────────────────────────────────────────┐
  │  PROCESS 2.4 — VALIDATE PAN (CONDITIONAL)                            │
  │  Input  : deposit_amount, pan_number                                 │
  │  Process: if deposit_amount > 50000:                                 │
  │             validate pan_number matches ^[A-Z]{5}[0-9]{4}[A-Z]$     │
  │  Output : validated pan or None                                      │
  │  Error  : 422 Validation Error if PAN missing or invalid format      │
  └──────────────────────────────────────────────────────────────────────┘
                │ PAN validated
                ▼
  ┌──────────────────────────────────────────────────────────────────────┐
  │  PROCESS 2.5 — GENERATE TOKEN NUMBER                                 │
  │  Input  : service_code_prefix, branch_id, booking_date               │
  │  Read   : D2 appointments (COUNT tokens with same prefix+branch+date) │
  │  Process: token = prefix + "-" + (100 + count + 1)                  │
  │  Output : token_number e.g. C-101                                    │
  └──────────────────────────────────────────────────────────────────────┘
                │ token_number
                ▼
  ┌──────────────────────────────────────────────────────────────────────┐
  │  PROCESS 2.6 — GENERATE QR HASH                                      │
  │  Input  : customer_id, branch_id, slot_start_time, booking_date      │
  │  Process: raw = "{customer_id}-{branch_id}-{slot}-{date}"            │
  │           qr_hash = SHA256(raw).hexdigest()  → 64 char hex string    │
  │  Output : qr_hash (unique per booking)                               │
  └──────────────────────────────────────────────────────────────────────┘
                │ qr_hash
                ▼
  ┌──────────────────────────────────────────────────────────────────────┐
  │  PROCESS 2.7 — SAVE APPOINTMENT                                      │
  │  Input  : all validated fields + token + qr_hash                    │
  │  Write  : D2 appointments (INSERT new record, status = BOOKED)       │
  │  Output : appointment_id + token_number + qr_hash → [CUSTOMER]      │
  └──────────────────────────────────────────────────────────────────────┘


--------------------------------------------------------------------------------
  DFD LEVEL 2 — PROCESS 3.0 KIOSK VERIFY (EXPLODED)
--------------------------------------------------------------------------------

  Input from [SECURITY]: qr_hash

  ┌──────────────────────────────────────────────────────────────────────┐
  │  PROCESS 3.1 — VALIDATE JWT & SECURITY ROLE                          │
  │  Input  : Bearer token                                               │
  │  Process: decode JWT → confirm role is SECURITY or ADMIN             │
  │  Error  : 403 Forbidden if role is CUSTOMER or TELLER                │
  └──────────────────────────────────────────────────────────────────────┘
                │
                ▼
  ┌──────────────────────────────────────────────────────────────────────┐
  │  PROCESS 3.2 — LOOKUP APPOINTMENT BY QR HASH                         │
  │  Input  : qr_hash                                                    │
  │  Read   : D2 appointments (WHERE qr_hash = input)                    │
  │  Output : appointment record                                         │
  │  Error  : 404 Not Found if no matching qr_hash                       │
  └──────────────────────────────────────────────────────────────────────┘
                │
                ▼
  ┌──────────────────────────────────────────────────────────────────────┐
  │  PROCESS 3.3 — VALIDATE STATUS IS BOOKED                             │
  │  Input  : appointment.status                                         │
  │  Process: confirm status == BOOKED                                   │
  │  Error  : 400 Bad Request if already CHECKED_IN, IN_PROGRESS etc.    │
  └──────────────────────────────────────────────────────────────────────┘
                │
                ▼
  ┌──────────────────────────────────────────────────────────────────────┐
  │  PROCESS 3.4 — UPDATE STATUS AND BROADCAST                           │
  │  Write  : D2 appointments (status = CHECKED_IN)                      │
  │  Trigger: WebSocket broadcast to all clients on branch_id            │
  │           { event: CHECKED_IN, token, appointment_id }               │
  │  Output : success message + token_number → [SECURITY]               │
  └──────────────────────────────────────────────────────────────────────┘


--------------------------------------------------------------------------------
  DFD LEVEL 2 — PROCESS 4.0 CALL NEXT TOKEN (EXPLODED)
--------------------------------------------------------------------------------

  Input from [TELLER]: branch_id, counter_id

  ┌──────────────────────────────────────────────────────────────────────┐
  │  PROCESS 4.1 — VALIDATE JWT & TELLER ROLE                            │
  │  Input  : Bearer token                                               │
  │  Process: decode JWT → confirm role is TELLER or ADMIN               │
  └──────────────────────────────────────────────────────────────────────┘
                │
                ▼
  ┌──────────────────────────────────────────────────────────────────────┐
  │  PROCESS 4.2 — VALIDATE COUNTER                                      │
  │  Input  : counter_id, branch_id                                      │
  │  Read   : D5 counters (confirm counter belongs to branch)            │
  │  Error  : 404 Not Found if counter not in branch                     │
  └──────────────────────────────────────────────────────────────────────┘
                │
                ▼
  ┌──────────────────────────────────────────────────────────────────────┐
  │  PROCESS 4.3 — FETCH NEXT CHECKED_IN APPOINTMENT                     │
  │  Read   : D2 appointments                                            │
  │           WHERE branch_id = input AND status = CHECKED_IN            │
  │           ORDER BY slot_start_time ASC, appointment_id ASC           │
  │           LIMIT 1                                                    │
  │  Error  : 404 Not Found if no customers waiting                      │
  └──────────────────────────────────────────────────────────────────────┘
                │
                ▼
  ┌──────────────────────────────────────────────────────────────────────┐
  │  PROCESS 4.4 — ASSIGN COUNTER AND BROADCAST                          │
  │  Write  : D2 appointments (status = IN_PROGRESS, counter_id = input) │
  │  Trigger: WebSocket broadcast to all clients on branch_id            │
  │           { event: CALLED, token, counter, appointment_id }          │
  │  Output : token_number + counter_number → [TELLER]                  │
  └──────────────────────────────────────────────────────────────────────┘

  SECTION 4 — USE CASE DIAGRAM

  ACTORS:  Customer  |  Teller  |  Security  |  Admin (inherits all)

  ┌─────────────────────────────────────────────────────────────────────────┐
  │                         BankQ System                                    │
  │                                                                         │
  │  ┌──────────────────────────────────────────────────────────────────┐  │
  │  │  <<use case>>  Register Account                                  │  │
  │  │  <<use case>>  Login                                             │  │
  │  └──────────────────────────────────────────────────────────────────┘  │
  │           ▲ (Customer, Teller, Security, Admin)                         │
  │                                                                         │
  │  ┌──────────────────────────────────────────────────────────────────┐  │
  │  │  CUSTOMER USE CASES                                              │  │
  │  │                                                                  │  │

  SECTION 5 — STATE MACHINE DIAGRAM (TOKEN LIFECYCLE)
================================================================================

  This shows all valid states and transitions for an Appointment token.

                         ┌─────────────┐
                         │   [START]   │
                         └──────┬──────┘
                                │ Customer submits booking
                                ▼
                    ┌───────────────────────┐
                    │        BOOKED         │
                    │  Token generated      │
                    │  QR hash generated    │
                    └───────┬───────┬───────┘
                            │       │
          Security scans QR │       │ Customer cancels
                            │       ▼
                            │  ┌─────────────┐
                            │  │  CANCELLED  │
                            │  └─────────────┘
                            │
                            ▼
                    ┌───────────────────────┐
                    │      CHECKED_IN       │
                    │  Customer inside      │
                    │  branch premises      │
                    └───────────┬───────────┘
                                │
                                │ Teller clicks Call Next
                                ▼
                    ┌───────────────────────┐
                    │      IN_PROGRESS      │
                    │  Customer at counter  │
                    │  Counter assigned     │
                    └───────────┬───────────┘
                                │
                                │ Teller clicks Mark Complete
                                ▼
                    ┌───────────────────────┐
                    │       COMPLETED       │
                    │  Service done         │
                    └───────────────────────┘
                                │
                                ▼
                         ┌─────────────┐
                         │    [END]    │
                         └─────────────┘

  VALID TRANSITIONS TABLE:
  ┌──────────────┬──────────────┬──────────────────────────────────────────┐
  │ From         │ To           │ Trigger                                  │
  ├──────────────┼──────────────┼──────────────────────────────────────────┤
  │ (new)        │ BOOKED       │ POST /appointments/book                  │
  │ BOOKED       │ CHECKED_IN   │ POST /kiosk/verify                       │
  │ BOOKED       │ CANCELLED    │ Customer cancels (future feature)        │
  │ CHECKED_IN   │ IN_PROGRESS  │ POST /teller/call-next                   │
  │ IN_PROGRESS  │ COMPLETED    │ POST /teller/complete                    │
  └──────────────┴──────────────┴──────────────────────────────────────────┘

  INVALID TRANSITIONS (rejected by backend):
    CHECKED_IN  → BOOKED       (cannot un-check-in)
    IN_PROGRESS → CHECKED_IN   (cannot go backwards)
    COMPLETED   → anything     (terminal state)
    CANCELLED   → anything     (terminal state)
